# 设置模块开发说明

后台用「系统设置」作一级菜单，每类设置有自己的二级页面，例如「系统设置 → 存储设置」。

系统设置和应用接入配置默认仅超级管理员可查看、修改。运营和客服看不到入口，直接请求配置页面或读写接口也由服务端拒绝。运营可在内容编辑页维护 Banner 和菜单，各管理员可在个人面板修改自己的外观，这些操作只开放对应页面和接口。

## 已确定的范围

- **接入参数**包括第三方密钥、证书和必要的配套信息，例如 COS 桶名。接入新服务时复用现有 `IntegrationSettings` 读取配置。
- **业务设置**包括已确认需要后台维护的参数，例如通知设置。每个业务模块定义自己用到的参数、校验和生效范围。分页条数等普通程序参数沿用代码默认值。
- **后台外观**支持超级管理员设置全后台默认样式，也支持每位管理员保存自己的偏好。换设备登录同一账号后可以沿用个人样式。

## 系统默认与局部覆盖

凡是有全局默认、又允许个别对象例外的设置，都遵循同一条规则：在「系统设置」维护默认值，在对象自己的页面改例外项。对象只保存明确改过的项。系统默认变化时，仍在继承的项自动跟随。清除某项覆盖后，它重新继承。各业务模块决定哪些项允许覆盖。

- **后台外观**：超级管理员在系统设置里改全后台默认样式。管理员在自己的外观面板改个人偏好。例如只改主题色，导航样式仍跟随后台默认。个人面板恢复默认时清除自己的覆盖，下次登录其他设备也跟随当前后台默认。
- **科室通知**：在系统设置里按事件维护医院默认通知群。在儿科编辑页可以只把“预约成功”改发儿科群。挂号业务按本科室、最近有有效配置的上级科室、医院默认依次取值。科室层级只属于挂号模块。

## 配置读取和保存

- 第三方接入参数依次从系统配置表、环境变量、Rails credentials 读取。只有 `nil` 和空白字符串允许回退，`0` 和 `false` 都是有效值。必填接入参数缺失时显示“未配置”。值无效或解密失败时直接报错。
- 数据库、Redis、`secret_key_base` 和加密主密钥属于启动配置，依次从环境变量和 credentials 读取。加密主密钥保存在数据库之外。
- 密钥用 Rails 内置加密能力入库。服务端校验该配置项的查看权限后，系统设置页和应用管理页在打开时直接显示当前生效的完整值及来源。留空或原样保存时保留原来源，只有明确改值才写入数据库。清除系统值后重新显示生效值及来源。
- 保存时按白名单校验字段、类型、格式和组合。仅更新本次提交的字段，相关项在同一事务提交。发生并发编辑时提示冲突，避免覆盖他人的更改。
- 事务提交后使相关缓存失效，按需刷新 Web 和 Sidekiq 使用的客户端。需要重启才能生效的配置应在页面明确提示。
- 仅向有该项查看权限的后台账号返回密钥原值。编辑前另行校验修改权限，审计记录操作人、变更项和结果。日志、异常正文、任务参数和小程序接口均不得包含密钥。真实凭据、主密钥及真实数据库导出不得提交仓库，示例、种子数据和测试使用演示值。

## 已交付的设置

超级管理员打开存储设置、选择 COS 时可直接查看生效的 SecretId、SecretKey、桶名、地域及 API 地址，每个字段旁标明来源。未指定 API 地址时按地域显示默认地址。留空或原样保存沿用原来源；若外部配置在打开页面后被轮换，旧表单须刷新后再保存。

- 系统页面归在 `admins/system_settings` 路由命名空间。超级管理员从一级菜单进入存储或外观页；旧存储页地址仍可使用。存储页继续调用 `StorageSettings`，包括留空保留密钥、清除后回退及提交后刷新客户端。
- 存储设置（含旧地址）和全局外观设置只向超级管理员开放查看和写入。侧栏、顶栏、账号菜单和页内导航按当前账号可访问的页面显示。列表为空时隐藏「系统设置」。超级管理员、运营管理员和客服都可用个人画笔修改或重置本人外观。
- 存储方式只接受 `local` 和 `tencent_cos`。所有来源都未配置时使用本地存储。遇到无效值时，超级管理员仍可进入存储页选择有效方式。清除成功时，日志只列出本次实际删除的数据库字段。保存失败的审计只记录允许的字段名和失败原因。若配置已提交而客户端刷新失败，页面提示已保存，日志单独记录刷新失败，下次后台请求或任务执行时重试。
- 外观的字段、可选值和初始默认值在 `AppearanceSettings`。全局差量保存在 `Setting` 的 `appearance` 行，个人差量保存在 `admins.appearance_overrides`。每次渲染按项目默认、系统默认、当前账号覆盖的顺序合并。升级时先运行 `bin/rails db:migrate`，再重启迁移前已运行的后台 Web 进程，使 Rails 读取新的字段列表。开发环境可用 `bin/rails restart`。
- 画笔面板即时预览，只向 `/admins/personal_appearance` 提交改动项。选择当前默认值或点击「跟随默认」会删除相应覆盖，「恢复默认外观」清空本人全部覆盖。写入时锁定记录并核对页面版本；遇到并发修改，刷新后再编辑。全局或个人外观写入失败时，页面提示未保存，回滚后记录操作人、涉及字段和失败原因。
- 旧浏览器偏好没有账号标识。后台及登录页清理原面板的已知 `tabler-*` 键，忽略旧链接中的外观参数。登录页以系统默认为起点，可临时预览；登录后读取当前账号的设置。

## 新模块怎样接入

1. **先讨论用途。** 用一个真实例子和用户确定谁能改、影响谁、哪些项允许覆盖、清除后取什么值。支付私钥可参考存储设置；医院默认通知群和科室例外可参考外观的逐项继承。
2. **接入现有入口。** 在 `backend/config/routes/admins.rb` 的 `system_settings` 下加单例资源。控制器和视图分别放在 `backend/app/controllers/admins/system_settings/`、`backend/app/views/admins/system_settings/`，二级菜单加入 `AdminsHelper#system_settings_pages`。模块负责本组字段、校验及保存后的生效逻辑。第三方凭据复用前述读写规则，允许局部覆盖的项在对象自己的页面维护。
3. **验收实际行为。** 用演示密钥验证超级管理员打开配置页即见原值，运营和客服看不到入口且无法直接读取或修改。检查日志不含原值，并验证留空保留和清除回退。用环境变量提供演示值，原样保存后应继续显示该来源。接入局部覆盖时，用两个对象验证只有修改过的项产生差异，更新系统默认后其他项继续跟随，清除后重新继承。

设置页面随实际模块接入。第 4 阶段接微信支付凭据，第 5 阶段接通知渠道，第 9 阶段接入挂号事件和科室通知覆盖。各阶段交付与留底节点见[开源版开发计划](开源版开发计划.md)。
