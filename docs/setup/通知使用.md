# 后台通知

超级管理员登录后按公众号配置回复内容和微信模板消息。先在应用管理中核对公众号名称与 AppID，填写本账号的 AppSecret，并在微信公众平台启用该账号的安全模式回调。操作见[部署与配置](部署与配置.md)。Web 和 Sidekiq 使用同一套数据库、加密配置和独立隔离的任务 Redis，启动方式见[本地运行](本地运行.md)。

## 配置并验证医院群通知

1. 超级管理员在「系统设置 → 企微通知设置」填写全院机器人 Key。留空保存保留现值，同一机器人更换 Key 时勾选轮换。
2. 在「通知管理 → 医院业务通知」只选择「退号待审核」，插入事件名称和预约号，核对示例预览，启用并保存。新安装默认关闭所有事件。
3. 在隔离环境使用虚构患者及支付、企微替身。开启医院退号审核，建一笔收费预约并模拟付款，此时发送记录应为空。从小程序申请退号，应在「通知管理 → 发送记录」看到一条该预约的待审消息。重复提交应仍是一条。
4. 按需启用「预约成功」「退号已办理」「患者取消待支付预约」「退款失败需处理」。分别用新免费预约、审核获批、未付主动关单、已验签的退款关闭结果核对事件和金额。停用后新结果跳过，重新启用不会补发历史。各事件字段和边界见[医院业务通知](../notifications.md#医院业务通知)。

医院退号审核有 Booking 业务状态。小程序版本审核目前由微信开发者工具和公众平台办理，直连模式没有接入版本审核结果。机器人和模板无法自动取得通过或驳回结果，历史发送记录保留。

## 在菜单和渠道码共用回复

1. 打开「回复内容」，选择公众号，新增一组名为「活动说明」的内容。添加文字「到了请去二楼签到」，再添加小程序卡片，选择目标小程序、输入页面路径，上传卡片封面。调整顺序，核对预览后保存。卡片封面使用当前公众号的微信素材。
2. 在「公众号自定义菜单」编辑「怎么签到」，选择这组回复，发布到微信。在菜单编辑器中新建回复，保存后可回到原草稿继续编辑。线上菜单在发布后切换。
3. 在「渠道二维码」新增「场馆门口」。只统计来源时填写名称即可。需要发送内容时选择扫码方式，包括欢迎语、专属回复或两者都发，并选择「活动说明」。
4. 几天后要给扫码的人加一句「请走东门」，从该码进入「编辑回复」，使用「仅改这个码」。保存时系统复制内容并绑定原码，可继续使用已印出的二维码。要让共用这组内容的入口一起变化，选择「更新全部」，核对页面列出的入口后再保存。
5. 在自动回复规则中，可将已有内容绑定到首次关注、再次关注或文字关键词。已关注用户再次扫码时使用该码当前的扫码配置，原关注来源保留。

旧菜单中能从微信读回原文的文字按钮，可点「沿用原文字」，核对原文并保存为回复内容。发布前，线上按钮继续使用原有内容。若旧菜单只留有点击 Key，应从原系统取得对应正文，再决定如何绑定。

## 绑定一次活动提醒模板

在「微信模板消息」选择当前公众号，找到「活动开始提醒」，选择已添加到微信公众平台的模板。核对每个微信字段及示例值，例如活动名称对应 `thing1`、开始时间对应 `time2`。实际字段名取自所选模板。确认并保存后，后续活动沿用这份绑定。

接入项目在业务事件发生时提供业务对象、收件人、实际数据和跳转页。下面的 `activity` 代表该项目已保存的活动，`official_account` 是接收授权的公众号。收件人传该公众号的 `UserApp` 身份，且粉丝当前已关注。一次事件重跑时沿用相同去重标识。

```ruby
Notifications::TemplateMessages.new(official_account).deliver(
  event: "activity_start",
  subject: activity,
  recipients: participating_fans,
  data: { activity_name: activity.name, starts_at: activity.starts_at },
  scheduled_at: activity.reminder_at,
  jump: { url: activity.public_url },
  idempotency_key: "activity-start-#{activity.id}"
)
```

入口返回每个去重后收件人对应的通知任务。活动时间、收件人筛选和跳转页由接入项目决定。新增事件时，参照 `backend/config/initializers/notification_events.rb` 登记字段的名称、类型和示例。拷贝到新项目后，应使用新项目自己的公众号、粉丝身份、模板和素材完成绑定。

## 查看和补发

从「发送记录」打开任务详情，逐条查看消息内容、次数和处理步骤。首条文字可作为微信回调的即时应答，后续卡片通过客服接口发送。生成了回调应答、渠道接受了请求、用户在微信里实际看到消息，是三个不同阶段。

企微通知先按事件文案替换变量，再把超出 2048 字节上限的正文按完整 UTF-8 字符顺序拆成多条，保留完整中文与管理员编排的消息顺序，每条独立记录结果。若原群机器人更换了 Key，在「企微通知设置」填写新 Key，并勾选「为原群机器人轮换 Key」。直接改为另一群的 Key 时，旧记录仍指向旧群。

渠道明确拒绝某条消息时，先按错误码或错误说明解决原因，再在该条下点击补发。可在操作日志按管理员和任务追溯这次操作。超时或进程中断留下的结果需要核对群内消息或微信记录，尚未开始的后续条目会继续发送。升级前的微信审核通知可从「发送记录 → 微信历史记录」查阅。
