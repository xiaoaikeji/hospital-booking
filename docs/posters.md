# Generic posters

Super administrators can open **通用海报**, upload a background, choose a scan destination, drag or resize the code, preview, save and download a full-resolution PNG. The two scan behaviors are explicit: follow an official account using one of its existing channel codes, or open a released mini-program page. Page paths and query parameters belong to the caller; no appointment, partner, referral or `links` dependency is embedded in the renderer.

`PosterSaving.call` validates and decodes the background, applies EXIF orientation, strips image metadata, records real dimensions and saves the attachment and audit in one transaction. Initial placement derives size and margin from the shorter side so wide or tall banners keep the QR code inside the image. Replacing a background without manually editing coordinates keeps the existing QR box if it fits, or shrinks/clamps it back inside the new dimensions; manually entered out-of-bounds coordinates still fail validation and preserve the persisted background and layout. New uploads use `MediaUpload` and the existing storage service. Backgrounds are served only through authenticated administrator routes; public Active Storage routes remain disabled.

`BookingPosterLayout` draws the background and code using original-image coordinates. The editor maps pointer locations from the CSS preview rectangle into that coordinate space. The same canvas is exported as PNG, so the download retains its original dimensions and placement. The selection outline and resize handle are HTML overlays and never enter the PNG. Replacing a background requires saving before another preview, so browser and server always use the normalized image.

`Wechat::PosterCode.fetch` accepts a mini-program page path and query, or an existing channel QR code belonging to the selected official account. It checks the account type and enabled status before reading images. Mini-program images are cached for 30 days per app, effective credential, page and query. Code generation and other WeChat operations share the same account-specific stable token.

The mini-program client uses WeChat's `getwxacode` endpoint so supplied query parameters reach the requested released page directly. WeChat limits the combined path and query to 128 bytes and applies account generation quotas. This first version does not introduce a short-link registry. Failed requests leave the editor's name, page, parameters, background and coordinates in place; retry preview explicitly. Changing the destination invalidates the displayed code, including an in-flight response from the previous selection.

Deploy with `bin/rails db:migrate` and restart Web processes. Reuse in another single-institution project requires changing the background and caller-provided destination, not the poster renderer. Real-account acceptance must still verify `getwxacode` permission/quota, released-page existence and parameter handling on actual devices, official-account channel subscription behavior and print scan quality.
