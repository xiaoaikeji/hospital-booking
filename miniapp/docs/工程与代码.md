# 工程与代码

## 页面和路由

- 禁止分包。所有页面放在主包的 `pages/<业务>/<页面>.vue`，在 `pages.json` 注册。每个业务一个目录，业务首页叫 `index.vue`，其他页面按用途平铺。具体业务目录随实际页面创建。
- 首页固定为 `pages/index/index.vue`。个人中心统一叫 `ucenter`。例如「我的 → 我的订单 → 订单详情」依次对应 `pages/ucenter/index.vue`、`pages/ucenter/orders.vue`、`pages/ucenter/order_detail.vue`。资料和设置也直接放在同级的 `profile.vue`、`settings.vue`。
- `pages.json` 用 Tab 缩进。`pages` 数组一个页面一行，同一行写完 `path` 和 `style`，`style` 先写 `navigationBarTitleText`。共用默认值放 `globalStyle`，页面按需写本页配置。`tabBar.list` 也是一个导航项一行，路径、文字和图标写在一起。
- 新增或改名页面时，核对页面文件、注册路径、跳转入口及涉及的底栏和分享链接。

## 文件放在哪里

| 位置 | 用途 |
| --- | --- |
| `pages/<业务>/components/` | 该业务的局部组件，由页面显式引入 |
| `components/` | 跨页面复用的交互组件 |
| `request/` | `http.js` 统一发请求，其他文件按业务提供接口 |
| `store/`、`utils/`、`config/` | 分别放跨页面状态、公共函数和配置；仅本页使用的状态留在本页 |
| `css/`、`static/` | 分别放公共样式和运行所需的静态资源 |
| `docs/` | 开发规范、各款小程序的页面参考资料 |

用到再建。几处只有外观相同，先共用样式；操作行为也相同，再提取公共组件。

## 命名和代码

| 对象 | 约定与示例 |
| --- | --- |
| 业务目录、页面、局部组件 | 小写英文，多词用下划线，如 `order_detail.vue`、`home_first.vue` |
| 公共组件 | `custom-` 开头，目录和文件同名，如 `components/custom-confirm-dialog/custom-confirm-dialog.vue` |
| 工具、图片、CSS 类名 | 小写短横线，如 `format-money.js`、`home-active.png`、`doctor-card` |
| JS 名称 | 变量和函数用小驼峰，如 `doctorList`、`submitAppointment()`、`canBook`。固定常量用 `PAGE_SIZE` |
| 接口字段 | 沿用后端约定，如 `doctor_id`、`appointment_no` |

页面使用 uni-app、Vue 3、`<script setup>`、JavaScript 和 SCSS。同目录引用用 `./`，跨目录可用 `@/`。格式遵循项目的 `.editorconfig`。注释写明决策原因。

外部组件优先从插件市场通过 `uni_modules` 引入实际需要的组件和依赖，用 `easycom` 按需加载。发行前核对主包体积与实际资源。

## 同一页面的多套外观

同一页面只注册一个入口。当前首页直接渲染第一套组件。后续有第二、三套时，各自增加组件，由同一个 `index.vue` 按确认的外观标识选择渲染，届时再确定标识来源。模板各自实现布局和操作顺序，共用的号源请求、预约提交和金额格式化集中维护。金额和单号遵循[项目根约定](../../AGENTS.md)。
